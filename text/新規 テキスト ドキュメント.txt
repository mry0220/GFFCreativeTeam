Animatorを使わない方法

スクリプト制御（コードで直接アニメーション再生）

Animatorの「State Machine」をほぼ使わずに、スクリプトでアニメーションを直接切り替える方法。

例えば：

animator.Play("Attack1");


条件分岐や遷移もスクリプト内で管理する。

メリット：

遷移を線で管理する必要がない

入力や技ごとの処理と同期しやすい

デメリット：

モーションが増えるとコードが長くなる

Animation Layer + Override

移動系、攻撃系などをレイヤーで分けて、必要なときだけ上書きする。

例：

Base Layer：Idle / Walk / Run

Attack Layer：剣振り / 技

LayerのWeightやOverrideで切り替え

Animatorを使うけど、線の遷移は最小限で済む

Playable API（Timelineっぽく動かす）

Unityの Playable API を使ってアニメーションをコードで制御

アニメーションを「シーケンス」として再生するイメージ

メリット：

入力や技のタイミングに合わせて自由に再生／キャンセル可能

State Machineを使わなくて済む

デメリット：

少し複雑で学習コスト高め

Animation Rig / Custom Controller

複雑な動きは「モーションデータを部分ごとに合成して再生」

例：剣振りは上半身だけ、下半身は移動モーションを継続

こういう場合もスクリプトで制御すると線の遷移は不要
